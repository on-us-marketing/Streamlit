# Second-Party Approval Rules

Last updated: July 2026
Status: Draft for review
Use stage: Master Content Brief and final review

## Purpose

This file controls how On-us references external partners, platforms, and second-party validation points. It reduces the risk of implying endorsement, exclusivity, investment, resale, or access to partner data without approval.

## Microsoft / Azure / Fabric

### Permitted Without Per-Use Approval

The following factual statements are allowed:

- On-us Intelligence is built on Microsoft Azure.
- On-us Intelligence uses Microsoft Fabric.
- On-us Intelligence was co-created with Microsoft.
- Microsoft / Azure / Fabric can be used as validation proof points for On-us' AI infrastructure story.

### Requires Approval Per Use

Ask for approval before:

- Implying Microsoft endorses On-us as a company
- Quoting any Microsoft employee
- Using "Microsoft partner" badge language
- Using Microsoft logos or screenshots
- Describing the relationship beyond the approved technical co-creation fact

### Never Use

Do not imply:

- Microsoft invests in On-us
- Microsoft resells On-us
- Microsoft guarantees On-us
- Microsoft endorses all On-us products
- Microsoft is responsible for On-us campaign performance
- On-us should be compared against or used to criticize competing foundation models

## Visa

For detailed Visa-specific wording, claim scope, VOP relationship rules, and DBS case usage logic, read:

```text
Tier 1 - Factual Foundation/visa_governance.md
```

### Permitted Without Per-Use Approval

The following factual statements are allowed:

- Smart E-Voucher with VOP is co-created with Visa.
- VOP refers to Visa Offer Platform.
- VOP supports card-linked, spending-based reward scenarios.
- Previously approved published results, such as Visa x DBS 3,000+ enrollments, can be referenced if the wording has already appeared in approved materials.

### Requires Approval Per Use

Ask for approval before:

- Using any new campaign statistic not previously published
- Describing On-us as Visa's "exclusive" or "sole" partner
- Using Visa logo or brand assets
- Quoting Visa employees
- Making claims about Visa strategy or Visa data

### Never Use

Do not imply:

- Visa endorses all On-us products outside the VOP context
- On-us has access to Visa data unless explicitly approved
- On-us is Visa's exclusive provider unless exact wording is cleared

## Google Wallet

### Permitted Without Per-Use Approval

The following factual statements may be used if confirmed in approved materials:

- On-us Smart E-Vouchers can be made available through Google Wallet.
- Google Wallet integration can support wallet-based reward visibility and redemption convenience.

### Requires Approval Per Use

Ask for approval before:

- Using Google logo or brand assets
- Quoting Google employees
- Saying Google endorses On-us
- Claiming direct commercial partnership beyond the approved integration wording
- Using new Google Wallet performance statistics

### Never Use

Do not imply:

- Google invests in On-us
- Google guarantees On-us performance
- Google shares user data with On-us
- Google endorses all On-us products

## General Second-Party Claim Rule

If a statement names a partner, ask:

```text
Is this factual?
Has this wording been approved?
Does it imply endorsement, exclusivity, investment, resale, data access, or guarantee?
```

If yes, flag for approval.
