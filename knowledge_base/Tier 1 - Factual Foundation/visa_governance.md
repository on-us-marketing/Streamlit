## What "Non-Cashback Benefits" Means

"Non-cashback benefits" is the term used to describe credit card rewards that are not direct cash rebates. These benefits may include merchant rewards, Smart E-Vouchers, travel benefits, lifestyle perks, and other value-added cardholder incentives.

Use this term when explaining how VOP helps issuers move beyond simple cashback mechanics and create more engaging card-linked reward experiences.

## Safe Context for Mentioning Visa

Use Visa only when the topic is clearly related to:

- VOP
- Visa Offer Platform
- Card-linked offers
- Issuer or cardholder engagement
- Credit card rewards
- Non-cashback card benefits
- Payment-linked reward journeys
- Bank or card scheme campaigns

Do not use Visa as a general credibility badge for unrelated On-us products.

## Claim Scope Rules

Visa-related content should follow the claim scope hierarchy:

```text
Company
-> Platform
-> Product / Solution
-> Campaign / Use Case
-> Client / Partner
```

Key rules:

- Visa is a third-party / partner reference.
- VOP is a product / solution context.
- A bank campaign result is campaign / use case level.
- A named bank or Visa x bank example is client / partner level.
- Do not move a Visa-related claim across levels unless the source clearly supports that exact level.

Example:

```text
Allowed:
On-us powers the Visa Offer Platform to deliver card-linked non-cashback benefits.

Not allowed:
Visa proves that all On-us Smart E-Voucher campaigns improve cardholder spending.
```

Reason: the first sentence is product-level approved wording. The second sentence turns a Visa relationship into a broad performance claim.

## Data and Privacy Framing

Use careful wording around data.

Use:

```text
campaign-level engagement and performance visibility, depending on approved data scope
```

```text
card-linked, spending-based reward scenarios
```

Avoid:

```text
On-us has access to Visa cardholder data.
Visa shares transaction data with On-us.
On-us uses Visa data for all campaigns.
```

Do not imply raw cardholder data access unless the exact statement has been approved.

Default safer options:

```text

```

```text
Anonymized metric mode:

```

Do not pair a named client with a performance number unless the current approval status confirms that the exact combination can be used externally.

If the source says "Visa x DBS 3,000+ enrollments" has appeared in approved materials, treat it as an approved-material reference, not a reusable default claim. For a new external asset, flag it for human confirmation.

## Requires Approval Per Use

Ask for approval before using:

- Visa logo or brand assets
- Visa employee quotes
- New Visa-related campaign statistics
- New Visa x client performance numbers
- Claims about Visa strategy
- Claims about Visa data
- "Exclusive", "sole", "official", or similar relationship wording
- Claims that Visa endorses, guarantees, resells, invests in, or certifies On-us
- Any Visa-related claim outside the VOP / card-linked offer context

## Never Use

Do not write:

```text
Visa endorses all On-us products.
On-us is Visa's exclusive reward partner.
On-us is Visa's sole provider.
Visa guarantees On-us campaign performance.
On-us uses Visa data for all campaigns.
Visa shares cardholder data with On-us.
All On-us products are powered by Visa.
```
